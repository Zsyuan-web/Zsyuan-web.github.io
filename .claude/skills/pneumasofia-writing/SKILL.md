# PneumaSofia 写作技能

本技能定义内容创作的执行标准。规范依据见 `docs/content-requirements.md`（最终依据）。

## 核心原则

> 详细内容见 `docs/content-requirements.md` 第一节"写作原则"。

- **先有引文路径，后有推导**：不是"先写内容再插引文"，而是"先锁定引文路径，再为每处引文设计推导"
- **引文关系决定论证方式**：引文之间是递进关系用逻辑链，是并列关系用并行列举。不是所有引文都走同一结构
- **描述，不指引**：让读者自己得出结论
- **并肩，不教导**：用"我们"，不用居高临下的"你"
- **逻辑推导，读者自悟**：概念在读者得出结论后才出现

## 人称使用规则

### 核心原则
人称根据语境灵活使用——抽象论述用"我们"，具体场景描述用"你"，论断性语句强化冲击力可用"你"。不机械，不强制。

### 正确示例
```
我们在找的不是任何具体的东西。我们在找一个不会变的东西。
（✓ 我们，抽象论述）

浏览器关掉。又打开。手指自己动的。
（✓ 有主语，具体场景）
```

### 错误示例
```
这就是为什么你读了那么多道理，却还是过不好人生。
（✗ 你，俯视教导）
```

## AI腔检测清单

### 词汇红牌（禁用）
`delve`、`tapestry`、`vibrant`、`landscape`（隐喻）、`nuanced`、`multifaceted`、`pivotal`、`crucial`、`foster`、`underscore`、`highlight`、`showcase`、`leverage`、`navigate`、`realm`、`intricate`、`comprehensive`、`robust`、`seamless`

### 过渡词禁用
`此外`、`其实`、`也就是说`、`值得注意的是`、`毫无疑问`、`这说明什么`

### 句式禁用
- "不是…而是…"过度使用
- "首先…其次…最后…"机械结构
- "一方面…另一方面…"套用
- "虽然在…但是…"强行转折
- "所以"、"因为"、"这说明"开头的推论句

### 空洞强调禁用
`这充分说明了`、`这表明了`、`这告诉我们`、`人生智慧在于`、`内心强大的人懂得`

## 引文规范

> 详细内容见 `docs/content-requirements.md` 第四节。

### 两种职责

| 职责 | 写法 | 示例 |
|------|------|------|
| **印证** | 分析走到某处读者已有共鸣，引文来印证"这个人也看到了" | 分析"找到就死"后，引用《中论》印证 |
| **升华** | 具体分析触及浅层，引文带出更深的维度 | 追问"为什么停不下来"后，引用《心经》点出空性 |

### 两种结构

**逻辑递进**：引文之间是层层深入的关系——前一处引文是台阶，后一处是台阶上的发现。适合核心论点需要多步推导的文章。

**并行列举**：多个引文从不同角度支撑同一个论点——没有谁是谁的台阶，它们并排站着，共同印证。没有层级递进，只有广度覆盖。

**如何选择：看引文之间的关系。**

如果引文 A 是 B 的前提、B 是 C 的前提，用递进结构。
如果引文 A、B、C 都是对同一个问题的不同回答，用并行列举。

```
递进示例：
A引文印证 → 读者认同 → B引文升华 → 读者看到更深一层

并列示例：
分析走到某处，读者已有共鸣
> A引文
> B引文
> C引文
三个角度，读者自己拼出全貌
```

### 格式

引文和翻译都用 `>` blockquote 包裹，整体是一个连续块：

```
> 原文（不加引号）
> ——《出处》
>
> 翻译：忠实准确，不自由发挥；如需进一步解释，在正文中另作说明
```

格式要求：
- 原文不加引号，直接跟在 `>` 后
- 出处单独一行，用 `——《出处》` 格式
- 翻译前空一行，与原文区分
- 翻译正文也要加 `>`，保持视觉统一
- **翻译标准：忠实准确，不自由发挥；如需进一步解释，在正文中另作说明**

### 禁止事项
- 禁止在引文前写"这说明什么"、"所以"、"因为"等推论性语句
- 禁止在引文前写"引用xxx的话来说"等目的性表述
- 禁止连着出现两处引文（引文之间必须有分析/举例段落）
- 禁止同一层面重复引用的核心观点

## 结尾规范

> 详细内容见 `docs/content-requirements.md` 第一节"结尾规范"。

结尾禁止：
- 固定句式（如"没什么大不了的"）
- 与前文相同的收尾方式
- 给答案

结尾根据文章自身走向自然生成：可以停在承认现实里、开放问题里、或者一个未被解决的张力里。

## 文章结构模板

> 详细内容见 `docs/content-requirements.md` 第三节"三步骤框架"。

### 三步骤框架（可选组合）

三步骤框架是**单篇文章内部**的写作结构参考，决定一篇文章内部引文之间的逻辑关系（是递进还是并列）。不是文章之间的导航关系，不同文章的联系只看概念本身的逻辑关联。

**夺境**：非常短，一段话。直接指出读者假设中的裂缝。不解释，不铺垫，不说教。

**用工具**：一步一步来，每个结论从前一步推出。不跳跃，不强行升华。概念名称在分析进行到一半时引入，不在段首摆出来。

**空空**：点到为止。不强求读者"到达"。停在开放问题里，或者承认现实里。

### 开场要求
以具体、感官化的场景切入。不许从概念定义开头。不许从"我们今天要讲…"

**禁止开场模式化**：不要每次都用"凌晨三点"开头。开场景必须针对当前主题——场景是主题的有机部分，不是通用模板。

### 禁止事项
- 章节编号（一、二、三、第一部分）
- 强行升华（"在这个浮躁的时代…"）
- 概念词典式开头（"X是…"）
- 对话式写作（"你问…XX说…"）
- 廉价安慰（"一切都会好起来的"）

## 自检清单

> 详细内容见 `docs/content-requirements.md` 第六节"自检清单"。

```
[ ] 没有"你应该"、"你要学会"、"你需要"
[ ] 没有"一切都会好的"、"你已经很棒了"
[ ] 没有偷懒连接词（显然、其实、也就是说、"这说明什么"）
[ ] 没有模式化开头（"凌晨三点"）
[ ] 引文在读者认同之后，不在开头
[ ] 每处引用前有一段自然推导，不是直接丢句子
[ ] 引文之间有分析/举例段落，不是连着出现两处引文
[ ] 引文之间层层递进，没有同一层面重复
[ ] 没有用"XX说"来替代自己的分析
[ ] 没有强行升华："在这个浮躁的时代……"
[ ] 没有概念词典式开头
[ ] 没有章节编号
[ ] 没有"你问：……XX说：……"的对话格式
[ ] 结尾停在承认现实里，或者开放问题里，不给答案
[ ] 逻辑链完整，每一步从前一步推出
[ ] 标题像朋友发消息，不学术不鸡汤
[ ] 用"我们"而不是"你"（大多数情况下）
[ ] 段落信息量饱满，没有用废话撑篇幅
[ ] 结尾没有多余的小尾巴（"也许"、"No big deal"等固定收尾）
[ ] 中英文引文数量一致——翻译时不得遗漏引文，不得合并引文
[ ] 中英文引文位置对应——英文引文出现在与中文相同逻辑位置
[ ] 语句意义明确——避免"你已经在了"等语义模糊的表达
```

## 心理阻力原则

让读者面对结论时，不只要承认"没有"，还要面对"那我之前的时间都白费了"这种心理代价。写出这种阻力，读者才会感到"被真实描述"，而不是被安慰。

**正确示例：**
- 停下来意味着承认：没有这个东西。从来没有。那我之前的寻找就会显得愚蠢。
- 不是"你不需要改变"，是"你一直在为一个不存在的东西努力"
- 不是"一切都会过去"，是"有些东西不会过去，而你投入的那些时间——也回不来了"

**错误示例：**
- "没关系，放下就好了"（廉价安慰，绕过了心理代价）
- "只要你愿意，你就能做到"（虚假希望，跳过了那个"愚蠢"的承认）

写一个结论之前，先问：读者面对这个结论要付出什么代价？如果代价没写出来，结论就是悬空的。

标题不要有固定句式。不要用"为什么……"开头。不要用"……的时候"的模式。不要起得像鸡汤或者学术论文。

标题应该让读者觉得"说的是我"，然后想点进去。用文章内容的核心意象。副标题说明主题概念，格式为"——副标题"。

**正确示例：**
- 搜了十年，答案从来没出现过——空
- 工具箱越来越满，水越来越少——道
- 骂了自己二十年，它变了吗——无我
- 抓了十九年，空掉了吗——空空

**错误示例：**
- 为什么你总是在找却找不到（固定句式）
- 凌晨三点的时候（模式化开头）
- 一切都会好起来的（鸡汤）

## 中英版本关系

英文版是翻译，中文版是定稿。写作时以英文读者为最终对象，中文版用来推敲逻辑和引文。

翻译标准：信（内容准确）、达（流畅自然）、雅（有文采）。

桥接在中文版写作时已完成（假设读者零文化背景），翻译时直接保留。中文版通过审查后，逐段翻译为英文。

## 翻译自检规范

翻译完成后，必须对照中英文进行以下检查：

**引文完整性：**
- 统计中文文章中 `>` 开头的行数（引文行），确认引文数量
- 英文文章引文行数必须与中文一致
- 每一处中文引文在英文中必须有对应引文，不能遗漏、不能合并

**引文位置对应：**
- 英文引文必须出现在与中文相同的逻辑位置
- 不能在翻译时将多处引文合并为一条
- 不能因"英文更流畅"而调整引文顺序

**检查方法：**
翻译完成后，用以下命令统计引文行数：
```bash
grep -c "^>" content/en/concepts/xxx.md  # 英文
grep -c "^>" content/zh/concepts/xxx.md  # 中文
```
两者引文行数应一致。

## 引文前置逻辑链原则

每一处引文都必须有充分的逻辑推导在前。引文是逻辑链的终点，不是结论的背书。

**正确结构：**
```
推导 → 读者自己走到引文边界 → 引文印证
```

**错误结构：**
```
结论 → 引文背书
```

检查每一处引文：如果把引文删掉，读者还能不能自己得出结论？如果不能，说明引文放在了结论之后，颠倒了。

## 桥接自然过渡原则

目标读者是海外用户，对中国文化背景零基础。当引入中国特有概念时，自然过渡，不固定句式。

**核心判断标准：** 每当用一个词来指代一个概念时，先想：这个读者听到这个词，会在脑海里浮现什么？如果什么也浮现不了，就需要桥接。

**正确示例：**
- 一切都是条件凑出来的……那个"没有底部"的状态，后来佛教里用一个词指它：空
- 它不是被找到的。它本来就在。……那个无法被定义、但万物都在其中的东西，在中文里叫"道"

**错误示例：**
- 在中国佛教里，有一个词专门描述这个发现：……被称为"空"（固定句式）
- 缘起。佛家叫这个。（跳跃，没有过渡）

如果前面已经对概念进行了桥接，后面引文的翻译里不要再重复解释。

## 结尾规范

结尾根据文章自身走向自然生成。禁止：

- 固定句式（如"没什么大不了的"、"也许"）
- 与前文相同的收尾方式
- 给答案
- 多余的小尾巴

结尾可以是：停在承认现实里、开放问题里、或者一个未被解决的张力里。

## 继续探索排序原则

每生成一篇新文章，必须同步更新所有相关文章的 `continueReading` 字段，确保"继续探索"部分按相关度排序——最相关的文章排在第一位。

**执行规则：**
- 新文章在前端数据中添加 `continueReading: [slug1, slug2, ...]`，列出当前文章最希望读者接下来阅读的文章（按优先级排序）
- 已有的相关文章需要将该新文章的 slug 插入到它们各自的 `continueReading` 中的适当位置（按相关度调整排序）
- 英文版和中文版各自独立维护 `continueReading` 字段（因为文章顺序可能因语言而异）

**相关度判断标准：**
- 概念递进关系：读完A最应该读B（如空→空空）
- 同一主题不同角度：A和B在讲同一个问题但切入角度不同
- 读者旅程：A是为B做准备的
