第0步：读取规范文件 + 知识图谱

每次写作前必须读取两份文件：

  • docs/content-requirements.md — 写作规范最终依据
  • knowledge-graph.json — 概念本体，所有引文必须来自知识图谱或经其扩展
Step 1 — 写作前
选题与规划：锁定引用路径
核心概念 → 知识图谱实体 → source/典故 → 递进路径设计 → 逐项写入规划文档

第1步：选题与规划

1.1 主题选择方法

主题不是拍脑袋选的。主题必须来自以下三个维度的交叉验证：

维度来源说明
搜索趋势Google 搜索建议、相关搜索、"人也在问"用户在搜什么？哪些问题有真实流量？
知识图谱缺口knowledge-graph.json 实体 + content-inventory/gaps/哪些核心概念还没有文章？哪些相关概念缺失？
系统性关联三步骤框架 + existing articles新文章与已有文章的关系是什么？看完所有文章是否形成整体理解？

一个有效的主题必须同时满足：① 有搜索需求（有人在找）② 知识图谱有支撑（不是空编）③ 与已有文章形成互补（不是重复）。

选题验证流程

① 搜索趋势调研
   WebSearch: "[目标概念] people_also_ask"
   WebSearch: "[目标概念] related_questions"
   → 提取真实用户提问

② 知识图谱匹配
   → 提取该概念的 knowledge-graph.json 定义
   → 确认有足够的引文支撑（source + related）

③ 缺口检测
   → 查阅 content-inventory/gaps/needed-articles.md
   → 确认该主题未被覆盖或需要升级

④ 交叉验证
   → 新文章与已有文章的引用不冲突
   → 新文章与已有文章形成递进或呼应
   → 读者看完所有文章后能形成对知识图谱的整体理解

选题确认后再进入 1.2 锁定知识图谱实体。

1.2 锁定知识图谱实体

确认文章主题对应的 knowledge-graph.json 实体：

文章主题对应实体source 字段related 实体

道dao《道德经》道可道wu-wei, ziran, wu
无我anatman《杂阿含经》色无常sunyata, anitya
无为wu-wei《道德经》天下之至柔dao, ziran, butcher-ding, empty-boat

实体未找到时的扩展流程

若在 knowledge-graph.json 中未找到对应实体，按以下流程扩展：

① 在 knowledge-base/ 中搜索相关经典文本（CBETA/CText）
   → 找到相关段落后，确定核心概念
② 为该概念创建新实体，填写以下字段：
   - id: 拼音无横线版本（如 xin-kong → xinkong）
   - termZh / termEn: 中英文名称
   - type: buddhist 或 taoist
   - definition: 概念定义
   - source: 扩展后的经典出处（多条）
   - related: 关联概念（可从 knowledge-graph.json 现有实体中匹配）
③ 更新 knowledge-graph.json：
   - 将新实体追加至 concepts 数组
   - 若与其他概念形成新映射，追加至 mappings
④ 扩展后的 source 字段示例：
   原始：《中论》诸法不自生
   扩展后：《中论》卷第一·诸法不自生，亦不从他生
              《杂阿含经》卷十二·缘起法
              《心经》·因缘生

扩展后实体示例

情况操作结果
有实体但 source 不足从 CBETA/CText 扩展引文至 source 字段source 字段包含 2-4 条经典引文
知识图谱中无该实体创建新实体 + 扩展 source新实体写入 knowledge-graph.json
概念属于西哲桥接范畴检查 mappings，若有新映射则追加mappings 包含新映射关系

重要：扩展实体后，必须同步更新 knowledge-graph.json，确保后续写作时能找到该实体及其 source。

1.4 封装：网页内容写作技能

技能名称：pneumasofia-writing

输入：knowledge-graph.json 实体（含 id、termZh、termEn、source、related）

输出：完整的中文文章初稿

该技能封装以下流程：

原章节技能内处理内容
1.4 设计引用递进路径根据 related 设计递进链（印证→深化→升维→收尾）
1.5 确认写作原则场景开头·逻辑链完整·无跳步推导·自然结尾
2.1-2.2 写作顺序与核心原则引文驱动逻辑：先锁引文路径→为每处引文设计推导
2.3 禁止事项禁止临时新增引文·禁止跳步推导
2.4 引文格式blockquote 样式·原文直接引出不加引号
2.5 修改内容检测并修复AI腔·跳步推导·格式错误·人称·结尾答案感

使用阶段：

阶段输入输出
生成阶段（Step 2）knowledge-graph.json 实体 + citationPaths完整文章初稿
修改阶段（2.5）当前文章草稿修改后的文章（去除AI腔、修复格式错误等）

技能内部流程：

阶段流程
生成阶段① 根据 related 设计引用递进路径（印证/深化/升维/收尾）② 从具体场景切入，设计每处引文的逻辑推导 ③ 引文印证读者判断，不是告诉读者该怎么想 ④ 自然收尾，无答案感 ⑤ 输出引文格式正确（blockquote 样式）的文章
修改阶段① 检测并修复说教语气 ② 检测并修复跳步推导 ③ 修复引文格式错误 ④ 调整人称自然度 ⑤ 修复结尾给出答案的问题

1.5 确认写作原则

规划阶段同时确认以下原则，不再写作时临时判断：

  • 每篇开头必须是具体感官化场景，不模式化，不通用"凌晨三点"
  • 人称根据语境灵活使用，不强制"你"或"我们"
  • 写作顺序：先为每处引文设计完整逻辑推导，再开始写
  • 每处引文都是逻辑链的终点，不是放在结尾的装饰
  • 结尾自然生成，禁止给答案
Step 2 — 写作中
生成中文版
场景开头 → 逻辑推导 → 引导至引文边界 → 引文印证 → 追问递进 → 下一处引文

第2步：生成中文版

本步骤通过调用 pneumasofia-writing 技能完成，详见 1.4 节技能说明。

2.1 写作顺序：引文驱动逻辑

每篇文章按以下顺序生成，引用在 Step 1 规划阶段已锁定：

① 针对第一处引文，设计一段完整的逻辑推导
   从具体场景切入 → 逐步追问 → 引文边界
② 引用原文 + 场景化翻译
③ 追问递进，设计下一处引文的逻辑路径
④ 重复①-③至引用用尽
⑤ 自然收尾（不给答案）
⑥ 调用 pneumasofia-writing 技能修改
⑦ 提交人工审查

核心变化：写作顺序不是"先写内容再插引文"，而是"先锁定引文路径，再为每处引文设计推导"。每一处引文都对应一段完整的逻辑链，由浅入深，暗中引导读者自己得出引文中的思想。

2.2 引文驱动逻辑的核心原则

每处引文不是"放在结尾的装饰"，而是"整段推导的终点"。

组成部分写法示例
场景入口具体、感官化，针对当前主题，不模式化"浏览器关掉。又打开。手指自己动的。"（空的主题：寻找）
逻辑递进每步追问，由浅入深，不跳步，不强行升华"为什么会这样？因为……但这说明什么？"
引文边界读者走到那里，自己得出判断，引文来印证分析到"找到就死"，读者已有共鸣
引用原文印证读者的判断，不是告诉读者该怎么想《中论》印证"找到就死"

禁止：分析段落写到一半就跳到引文。引文必须在整段逻辑链的终点。

2.3 禁止事项

详细禁止清单见 docs/content-requirements.md 第二节。本步骤新增操作层禁止：

禁止说明
临时新增引文引用路径在 Step 1 锁定，写作时不允许临时添加，必须先改规划
跳步推导"显然"、"其实"、"也就是说"代替不了真正的推导

2.4 引文格式

详细引文规范见 docs/content-requirements.md 第四节。格式摘要：

原文（段落中直接引出，不加引号）
——《出处》

翻译（场景化翻译）：口语化、3句以内

2.5 使用写作技能修改内容

完成初稿后，调用 pneumasofia-writing 技能对当前写作内容进行修改（技能说明见 1.4 节）。

技能将自动检测并修复：

  • 说教语气（"你应该"、"需要"、"必须"）
  • 跳步推导（"显然"、"其实"）
  • 引文格式错误
  • 人称不自然
  • 结尾给出答案

2.6 人工审查

自检通过后提交人工审查。审查要点：

  • 说教味（"你应该"类指示性语气）
  • 目的性（引文前推着读者走）
  • 引文布局是否均匀
  • 逻辑链是否完整

人工审查提出的通用性要求，同步更新至本流程文档和 docs/content-requirements.md。

Step 3
英文版（重写，非翻译）
基于通过审查的中文版重写 · 嵌入西哲框架 · 引文来源一致

第3步：英文版（重写，非翻译）

中文版通过审查后，以中文版为蓝本重写为英文版（不是逐字翻译）。英文版需要：

  • 为西方读者熟悉的概念框架搭桥（Nietzsche/Camus/Nishitani/Heidegger）
  • 引文优先使用 CBETA/CText 原文，可额外引用西方哲学原典
  • 核心论证与中文版一致，表达方式适配西方读者

英文版自检

没有指示性语气（"you should", "you need to"）
有西哲框架桥接
引文分布均匀
结尾停在开放问题或承认现实
英文版与中文版核心论证一致

第4步：发布
